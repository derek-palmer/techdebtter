# Use GitHub Issues for findings

Raw Detector output remains a Detection until TechDebtter validates, deduplicates, groups, classifies, and prioritizes it through Triage. Source-specific Detection Fingerprints preserve provenance, while a normalized Finding Fingerprint lets equivalent Detections from different tools converge. Each independently actionable condition that survives Triage becomes a Finding whose durable system of record is one GitHub Finding Issue in the affected repository; multiple related Detections may support that Finding when they share one remediation. Each Finding Issue combines a human-readable title and body, workflow labels, and a hidden versioned metadata block for fingerprints, provenance, schema version, and reconciliation. TechDebtter may retain transient or operational state, but it will not maintain a competing authoritative finding backlog outside the engineering team's existing workflow.
